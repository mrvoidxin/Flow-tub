## Push + CI (same session, later)
- The user supplied a **classic PAT with `repo` + `workflow`** scope, which fixed
  everything. Always ask for the `workflow` scope too when a branch edits
  `.github/workflows/*.yml` — GitHub rejects such pushes without it.
- Pushed `flowtube-rebrand`, opened **PR #7**, and enabled GitHub Pages via
  `POST /repos/:o/:r/pages -d '{"build_type":"workflow"}'` (404 on GET before =
  Pages was never enabled; the POST returns 201 and `html_url`
  `https://mrvoidxin.github.io/Flow-tub/`).
- **CRITICAL: `minSdk` must stay 26.** Lowering it to 24 (to match an
  "Android 7.0+" claim) hard-fails the build: the vendored Snowball stemmers
  (`org/tartarus/snowball/SnowballProgram.java`) call
  `MethodHandle.invokeExact`, and D8 errors
  `MethodHandle.invoke and MethodHandle.invokeExact are only supported starting
  with Android O (--min-api 26)`. Symptom is asymmetric: **release R8 only
  WARNs** (the calls get inlined away, `SnowballProgram` ends up absent from the
  DEX) so `assembleGithubRelease` succeeds, but **`assembleGithubDebug` fails
  outright** and CodeQL's `Build for extraction` step (which builds the debug
  variant) goes red. A release APK built at minSdk 24 would also crash on API
  24/25. Restored 26 and fixed the README badge / requirements line / landing
  page to say Android 8.0+ (API 26).
- Upstream README never said "Android 7.0+"; it said Android 8.0+ and pointed at
  `assets.flow-tube.org` badge SVGs, which were replaced with shields.io badges
  during the rebrand. Do not restate an SDK floor from the docs — read
  `app/build.gradle.kts`.
- CI after the fix: Build APK + CodeQL green. `Android CI/CD` runs ~30+ min
  because `Lint GitHub nightly` is very slow; poll the run id rather than
  assuming failure.
